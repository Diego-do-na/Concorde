# ml/ — CONCORDE offline pipeline

Python only, never in the serving path (AGENTS.md, ADR-001/ADR-002). This
directory holds the offline dataset, feature, training and export pipeline
that feeds the Rust `api/` service's ONNX model — see `docs/CONCORDE_Especificacion_Tecnica_v1.0.pdf`
§10 for the full data/model plan.

## Dataset location convention

The altur-challenge practice dataset (`manifest.csv`, `audio/`, `turns/`) is
**never committed** (AGENTS.md, NFR-011, §13.4) — every script here reads it
through `ml/common/dataset.py`, which resolves the dataset root from the
`CONCORDE_DATASET_DIR` environment variable (see `product/.env.example`),
falling back to Diego's original path
(`/Users/diego/Desktop/Proyects/HackMty/hackmty26`) if unset.

Expected layout under that root:

```
<CONCORDE_DATASET_DIR>/
    manifest.csv          anon_id,label,split,duration_s
    audio/<anon_id>.wav    stereo 8 kHz 16-bit PCM (ch0 = caller, ch1 = agent)
    turns/<anon_id>.json   {"turns": [{"channel": 0|1, "start": s, "end": s}, ...]}
```

`turns/<id>.json` exists only in this practice dataset — the served system
computes its own turns via VAD (ADR-003) and never sees this file.

`ml/common/dataset.py` exposes:

- `load_manifest()` — the full manifest as a `pandas.DataFrame`.
- `load_turns(anon_id)` — `list[(channel, start, end)]`, time-sorted.
- `wav_path(anon_id)` — `Path` to the raw audio (never opened by `api/`).
- `iter_split(split=None)` — iterate manifest rows for `"train"`, `"val"`,
  or all rows.

## Behavioral feature contract (fc-1, §9)

`ml/features/extract.py` is the single source of truth for the fc-1
feature vector — the Rust production extractor (`api/src/features/`, T014)
mirrors it line by line. The frozen name/order list lives in
`product/artifacts/feature_contract_fc-1.json`; `ml/features/contract.py`
asserts `extract()` matches it. **fc-1 has 23 floats for 22 feature IDs**
because F-21 (`silence_break_delay`) is defined in §9 as two values (mean
and CV), split here into `silence_break_delay_mean` and
`silence_break_delay_cv`.

`extract(caller, agent, duration_s) -> np.ndarray` takes already
channel-split lists of half-open `(start, end)` intervals — this is
"turns-shaped", so it runs identically over `turns/<id>.json` (practice
dataset) and over this system's own VAD output at serving time (ADR-003);
neither caller passes a channel column.

Global degenerate-input rule (never NaN/inf): every statistic computed
over an empty set of values defaults to **mean/median/std/min = 0.0**;
every ratio or rate with a zero denominator defaults to **0.0**; every
`_cv` (`std / mean`) defaults to **0.0** when `mean == 0.0` instead of
dividing by zero. `_stats()` and `_cv()` in `extract.py` are the two
choke points that enforce this — no other code path in the module
performs a raw division or calls `numpy` reduction functions directly on
a value list.

| ID | Feature | Degenerate-input rule |
|---|---|---|
| F-01 | `resp_latency_mean` | 0.0 if no agent turn has a following caller turn |
| F-02 | `resp_latency_median` | 0.0 under the same condition |
| F-03 | `resp_latency_std` | 0.0 (population std, `ddof=0`); 0.0 if the set is empty |
| F-04 | `resp_latency_cv` | `std/mean`, 0.0 whenever mean is 0.0 |
| F-05 | `latency_monotony_index` | fraction of latencies within ±0.15s of the median; 0.0 if the set is empty |
| F-06 | `resp_latency_min` | 0.0 if the set is empty |
| F-07 | `overlap_count` | 0 if either channel has no turns |
| F-08 | `overlap_rate_per_min` | `F-07 / (D/60)`; 0.0 if `D <= 0` |
| F-09 | `overlap_total_dur` | 0.0 if no overlapping pair exists |
| F-10 | `caller_bargein_count` | 0 if no caller turn starts strictly inside an agent turn |
| F-11 | `recovery_delay_mean` | 0.0 if no overlap event has a caller turn starting at/after its end |
| F-12 | `recovery_delay_cv` | 0.0 under the same condition, or when only one such event exists (std=0) |
| F-13 | `recovery_abort_ratio` | abort-count / `overlap_count` (F-07); 0.0 if `overlap_count` is 0 |
| F-14 | `caller_turn_dur_mean` | 0.0 if the caller has no turns |
| F-15 | `caller_turn_dur_std` | 0.0 under the same condition (or a singleton turn) |
| F-16 | `caller_turn_dur_cv` | `std/mean`, 0.0 whenever mean is 0.0 |
| F-17 | `short_turn_ratio` | fraction of caller turns with duration **strictly** `< 1.0s`; 0.0 if no caller turns |
| F-18 | `fragmentation_rate` | consecutive same-channel caller pairs with gap **strictly** `< 0.5s`, per minute of `D`; 0.0 if `D <= 0` or fewer than 2 caller turns |
| F-19 | `caller_speech_ratio` | `Σcaller / D`; 0.0 if `D <= 0` |
| F-20 | `speech_balance` | `Σcaller / Σagent`; 0.0 if the agent never spoke |
| F-21a | `silence_break_delay_mean` | 0.0 if no mutual-silence gap `> 2.0s` is ever broken by the caller |
| F-21b | `silence_break_delay_cv` | 0.0 under the same condition, or a singleton gap |
| F-22 | `turn_count_caller` | 0 if the caller never speaks (not itself degenerate — used as normalising context for F-17/F-19) |

Interpretation notes that go beyond the one-line §9 definitions (mirrored
in the Rust extractor, T014):

- **Overlap** between an agent turn `a` and caller turn `c` is the
  standard half-open interval test `a.start < c.end and c.start < a.end`;
  the overlap span is `[max(a.start, c.start), min(a.end, c.end))`.
- **Recovery delay** (F-11/F-12) is measured from an overlap event's end
  (`min(a.end, c.end)`) to the *first* caller turn starting at or after
  that point — the same "first turn at or after a threshold" pattern §9
  uses for F-01's response latency. If no such caller turn exists (the
  overlap is the last thing that happens), that event contributes nothing
  to the mean/CV set — it still counts toward `overlap_count`, so
  F-13's abort ratio and F-11/F-12's mean/CV can have different effective
  denominators by design.
- **Recovery abort** (F-13) compares the caller turn's own end to the
  overlap's *onset* (`max(a.start, c.start)`), independent of whether a
  next caller turn exists.
- **Mutual-silence gaps** (F-21) are computed over the union of both
  channels' turns merged into busy spans, including the silence before
  the first turn and after the last turn up to `D` — a call that never
  speaks at all is one large silence gap from `0` to `D`. For each gap
  exceeding 2.0s, the delay is measured from the *start* of the gap
  (when both channels went silent) to the first caller turn starting at
  or after that point.

## Dataset build: fc-1 tables from both turn sources (T016)

`train/build_dataset.py` computes the fc-1 vector for every one of the
353 calls in `manifest.csv` **twice**: once from the practice dataset's
ground-truth `turns/<id>.json` ("ref") and once from this system's own
Rust VAD, invoked via the release `vad-dump` binary ("vad") — the exact
turns shape `/detect` produces at serving time, since `turns/<id>.json`
only exists in this practice dataset (ADR-003, FR-004).

```bash
cd product
cargo build --release --bin vad-dump   # once, or let build_dataset.py do it
cd ml
python -m train.build_dataset
```

Writes (all under `ml/data/`, gitignored, never committed — NFR-011):

- `ml/data/features_ref.parquet` — ground-truth-turns vectors.
- `ml/data/features_vad.parquet` — **the training table.** T017+ trains
  on this one, never on `features_ref`: training must see the same
  turns the served system will actually produce, not the oracle
  `turns.json` that only exists here — training on `features_ref` would
  itself be a training/serving skew bug (R-01, FR-004/ADR-003).
- `ml/data/skew_report.md` — for each of the 23 fc-1 features, the mean
  absolute difference between the two sources and their Spearman rank
  correlation across all 353 calls; any feature with correlation below
  0.7 (or undefined, when one source is constant across every call) is
  flagged **VAD-sensitive** — R-01 evidence for T017 to watch, since a
  feature that swings depending on which turns source produced it is a
  candidate for high train/serve variance.

Both tables share the same columns: `anon_id`, `label`, `split`,
`duration_s`, the 23 fc-1 feature names in contract order, `source`
(`"ref"` or `"vad"`). The build is idempotent — every run recomputes
both tables and the skew report from scratch and overwrites the three
files; it also re-asserts the fc-1 contract (`features/contract.py`)
before touching anything, so a drifted feature order fails loudly
instead of silently producing a mislabeled table.

## ADR-012 deviation: no speaker ID in this dataset

`manifest.csv` has no speaker-identifier column, and the dataset terms
forbid attempting to identify any speaker (§13.4, NFR-011) — so ADR-012's
"speaker-grouped cross-validation inside `train`" cannot be implemented
literally, and must **not** be approximated by clustering voices (that
would itself be a form of speaker identification). The documented fallback
for T016/T017: **stratified K-fold by `anon_id` inside `train`**; `val`
remains the only speaker-disjoint measurement, and stays untouched outside
final measurement/calibration either way.
